## Objectives

- o-1: after reading, the reader can explain the difference between declaring a desired state ("3 copies of storefront") and issuing commands ("start storefront on machine 04"), using a management analogy (goals vs. task lists) and saying where that analogy breaks; and can say that writing down an intention (applying a manifest) records it rather than running anything (m-04).
- o-2: after reading, the reader can describe the reconcile loop (observe → compare → act, repeated, by many independent controllers rather than one master brain) and use the loop lens, "which loop, watching what, doing what?", to predict what happens when a pod or a whole machine dies, including roughly how long it takes and what the loop does not fix (m-03, m-27 revisited).
- o-3: after reading, the reader can explain what a pod is (a wrapper around one or more containers, scheduled as a unit) and why pods are treated as disposable (replaced, not repaired; a replacement is a new pod), and what that requires of the application, including why endless restarts of a broken app are the loop working, not a fix (m-05, m-06).
- o-4: after reading, the reader can sketch the cluster at a high level (control plane with the API server as the record of intent; nodes running pods) and say which parts a managed provider runs and which remain the company's.

## Research questions

- q-1 (o-1): What precisely happens when a manifest is applied: what the API server does (validate, store as desired state in the cluster's record), and at what point anything starts running? State it accurately for a manager without etcd or admission-chain detail. (m-04)
- q-2 (o-1): How do the Kubernetes docs and well-known engineering sources describe declarative vs. imperative management, and how far does the management analogy (setting goals vs. handing out task lists; a delegated owner who watches one number) hold? Where exactly does it break (no judgment, no negotiation, keeps acting forever, "level-triggered" behaviour)?
- q-3 (o-2): How do controllers work (watch the API server, compare desired with observed, act; independent; each owns one kind of thing), and is there any single component that "commands every action"? Which common retellings overstate a central brain? (m-03)
- q-4 (o-2): When a node dies on a managed cluster, which loops act, in what order, and roughly how long it takes with default settings (node marked not ready, pods evicted or marked for replacement, a replacement pod created by the replica-set loop, placed by the scheduler, started by the node agent, image pulled)? Give sourced default timings, hedged, so "minutes, and nobody wakes up" is accurate and not "instant".
- q-5 (o-2, o-3): What does the loop not fix: an app that crashes on start (crash-looping with growing back-off delays), no room left on the remaining machines, lost data? State each accurately in plain words without Ch 5–10 vocabulary. (m-05)
- q-6 (o-3): What exactly is a pod (one or more containers sharing network identity and storage, the smallest thing Kubernetes schedules), is "one container per pod" the common case, and what changes when a pod is replaced (new name, new address, not the same pod)? What do newcomers get wrong? (m-06)
- q-7 (o-3): What does "disposable" require of an application in practice (no important state inside the pod, tolerating restarts, shutting down cleanly when asked, starting reasonably fast), at a manager's level? Cite a recognised source such as the twelve-factor app's "disposability", if accurate.
- q-8 (o-4): What are the control-plane components (API server, the cluster's record, scheduler, controller manager, cloud controller manager) and the node components (node agent/kubelet, container runtime), and which of them does a manager need by name?
- q-9 (o-4): On the major managed services (EKS, GKE, AKS, kept generic in the text), what does the provider run and operate, and what does the customer still own (nodes or node pools, depending on the mode; workloads; version upgrades)? Current, sourced facts; no pricing beyond whether a control-plane fee exists, and only if needed.
- q-10 (o-2): The name: is "Kubernetes" Greek for helmsman/pilot, and is "K8s" a numeronym (8 letters between K and s)? Sourced from the project itself. Is the helmsman image worth using for the reconcile loop (a helmsman continuously corrects toward a heading)?
