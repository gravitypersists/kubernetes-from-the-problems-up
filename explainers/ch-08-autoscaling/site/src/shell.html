The Friday dinner rush: autoscaling

Every Friday evening Fennel’s orders triple for two hours. This chapter follows the two loops that add copies and machines for the rush and take them away afterwards, the one Friday that didn’t go smoothly, and what it all did to Morgan’s bill.

Sources

  1. Kubernetes documentation, “Horizontal Pod Autoscaling”: the calculation, the default 15-second interval and 10% tolerance; processor use measured as a share of each Pod’s request, and no action where a request is missing; the minimum and maximum; how Pods that aren’t ready yet are counted; the five-minute look-back before lowering the number; other measurements; and the walkthrough, on a number capped by the maximum.
  2. Kubernetes Autoscaler project, Cluster Autoscaler FAQ: nodes are added only for Pods that failed to schedule; the 10-second check; identical machines within a node group; when a node is removed (under half reserved, its Pods fit elsewhere, for 10 minutes) and what prevents it; the 15-minute wait for a requested node.
  3. Kubernetes documentation, “Node Autoscaling”, and Karpenter, “Concepts”: tools that choose a machine to fit the waiting Pods without pre-made groups.
  4. Microsoft, “Cluster autoscaling in Azure Kubernetes Service”: a minimum and a maximum node count per node pool; waits of up to 30 minutes after failed requests; and “Node auto-provisioning”.
  5. Google Cloud, “About GKE cluster autoscaling”: a minimum and maximum size per node pool; a first retry after five minutes, growing to 30.
  6. AWS, EKS Best Practices Guide, “Cluster Autoscaler”: new nodes can take multiple minutes; spare room kept with placeholder Pods trades cost for speed.
  7. AWS Containers Blog, “Faster nodes, smarter scaling: what’s new inside Amazon EKS Auto Mode” (23 June 2026): nodes ready in under 25 seconds on most machine types, by AWS’s own measurement; one customer’s 23-minute delays; and the EKS Auto Mode guide.
  8. AWS, “Spot Instances”, read 16 November 2026: a two-minute warning before a spot machine is taken back.
  9. PostgreSQL documentation, “Connections and Authentication”: the maximum number of connections, typically 100 by default.
  10. Kubernetes documentation, “Vertical Pod Autoscaling”, and KEDA, “KEDA Concepts”: the two other kinds of autoscaling named in §02.
