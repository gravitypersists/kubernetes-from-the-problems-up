# Parking lot

- Ch 8: the cluster autoscaler (or provider node autoprovisioning) adds nodes when Pods are pending for lack of room and removes underused ones; AKS Automatic "creates nodes based on workload requests using Node Autoprovisioning". This chapter may only say "we'll name this later" (https://learn.microsoft.com/en-us/azure/aks/intro-aks-automatic)
- Ch 8: requests can be resized "based on actual usage patterns", including in-place resize of a running Pod; recommenders and vertical autoscaling are Ch 8's to name (https://kubernetes.io/docs/concepts/configuration/manage-resources-containers/)
- Ch 8: GKE Autopilot "manages Pod bin-packing for you" and AKS Automatic says "Pods are bin packed efficiently": fully managed modes pack, standard defaults spread (https://cloud.google.com/kubernetes-engine/docs/concepts/autopilot-overview)
- Ch 8 / engineer territory: switching the scheduler to packing (`MostAllocated`) is a scheduler configuration setting; managed providers expose it differently (e.g. a GKE autoscaling profile; not verified here) (https://kubernetes.io/docs/concepts/scheduling-eviction/resource-bin-packing/)
- Ch 11: namespace defaults for requests and limits (LimitRange) and per-team totals (ResourceQuota); with a LimitRange, an unset limit is filled in automatically (https://kubernetes.io/docs/tasks/configure-pod-container/assign-memory-resource/)
- Ch 11 / Ch 12: Pod priority and preemption: the scheduler can remove lower-priority Pods to place a higher-priority pending one, and priority also orders evictions (https://kubernetes.io/docs/concepts/scheduling-eviction/node-pressure-eviction/)
- Ch 12: QoS classes (Guaranteed, Burstable, BestEffort) are how engineers predict eviction order; the node agent doesn't use them directly ("The kubelet does not use the pod's QoS class to determine the eviction order") (https://kubernetes.io/docs/concepts/scheduling-eviction/node-pressure-eviction/)
- Ch 12: default hard eviction threshold is `memory.available<100Mi` on Linux; node-pressure eviction ignores PodDisruptionBudgets and graceful shutdown periods for hard thresholds (https://kubernetes.io/docs/concepts/scheduling-eviction/node-pressure-eviction/)
- Ch 12: memory limits are enforced "reactively", only when the kernel detects memory pressure, so a container can briefly exceed its limit; MemoryQoS (cgroup v2) adds memory throttling (https://kubernetes.io/docs/concepts/configuration/manage-resources-containers/)
- Ch 12: the scheduler's retry back-off defaults (1 s initial, 10 s maximum) and queueing hints (https://kubernetes.io/docs/reference/config-api/kube-scheduler-config.v1/)
- Ch 10: memory-backed `emptyDir` volumes count toward a container's memory limit, so writing temporary files can cause an OOM-kill (https://kubernetes.io/docs/concepts/configuration/manage-resources-containers/)
- Ch 10 / Ch 14: the default spreading also spreads copies across zones (maxSkew 5), a resilience topic (https://kubernetes.io/docs/concepts/scheduling-eviction/topology-spread-constraints/)
- Ch 12 / Ch 14: Spot VMs get a short graceful shutdown when reclaimed (GKE default 30 s for Pods) (https://cloud.google.com/kubernetes-engine/docs/concepts/spot-vms)
- Ch 14: control-plane fees: GKE "A flat cluster management fee of $0.10 per cluster per hour" in every mode; EKS "a per cluster per hour fee based on the cluster's Kubernetes version" ($0.10 in standard support) (https://cloud.google.com/kubernetes-engine/pricing; https://aws.amazon.com/eks/pricing/)
- Ch 14: GKE Autopilot doesn't bill Pods that are waiting to be scheduled, but does bill crash-looping ones; Pods that select specific hardware switch to node-based billing plus a premium (https://cloud.google.com/kubernetes-engine/pricing)
- Ch 14: EKS Fargate runs one Pod per node and requires requests equal to limits; its pricing page says "resources used" where the docs mean the provisioned size (https://docs.aws.amazon.com/eks/latest/userguide/fargate-pod-configuration.html)
- Ch 14: CNCF's earlier FinOps microsurvey (2021, 195 respondents, April–May 2021) found 68% saw Kubernetes costs rise; not comparable with 2023 (secondhand via search summary, not fetched) (https://www.cncf.io/blog/2021/06/29/finops-for-kubernetes-insufficient-or-nonexistent-kubernetes-cost-monitoring-is-causing-overspend/)
- Ch 14: CNCF 2023: second-ranked cause of overspend was "a lack of awareness of responsibility at an individual or team level" (45%); cost ownership is a platform-team question (https://www.cncf.io/blog/2023/12/20/cncf-cloud-native-finops-cloud-financial-management-microsurvey/)
- Ch 14: Datadog: "We don't expect that wasted container spend can be eliminated entirely"; some idle room is the price of uncertainty (https://www.datadoghq.com/state-of-cloud-costs/)
- Engineer territory: processor requests also act as a weighting under contention ("workloads with larger CPU requests are allocated more CPU time") (https://kubernetes.io/docs/concepts/configuration/manage-resources-containers/)
- Engineer territory: a limit with no request gets the limit copied as its request (https://kubernetes.io/docs/concepts/configuration/manage-resources-containers/)
- Engineer territory: load-aware placement (by live usage) exists only as add-ons outside the default scheduler (model; not researched)
